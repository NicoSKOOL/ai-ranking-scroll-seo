# Multi-language scroll sites (Astro output mode)

A single HTML file cannot carry three languages cleanly. For multi-language
builds use Astro with static output:

- One content file per language (`src/content/es.json`, `en.json`, `pt.json`),
  one component tree, one route per language (`/`, `/en/`, `/pt/`). The primary
  market's language sits at `/`.
- Each language has its own primary keyword, title, H1 and description, chosen
  from that market's search data. Never translate a keyword; research it.
- `<html lang>` per route; self-referencing canonical; reciprocal
  `hreflang` for every language plus `x-default` pointing at the primary.
- The language switcher is a set of real links to the equivalent routes, with
  `hreflang` and `lang` on each and `aria-current="page"` on the current one.
- Anything the engine renders from numbers (counters) must use the page locale:
  `data-sc-count-locale="auto"` (15.000 in es/pt, 15,000 in en).
- Localise the scene, not just the words, when it is cheap: the flight map puts
  the page's own market first in its labels.
- Pin `output: 'static'` in astro.config. `wrangler deploy` autoconfig adds the
  Cloudflare server adapter to Astro projects; a static scroll site does not
  need it, and it moves the build output to `dist/client`.
- Deploy: Cloudflare Workers static assets (`wrangler.jsonc` with
  `assets.directory: ./dist`). Staging stays noindex (meta + `X-Robots-Tag` in
  `public/_headers`).
